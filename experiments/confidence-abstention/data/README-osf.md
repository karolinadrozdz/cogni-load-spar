# Causal Evidence that Language Models use Confidence to Drive Behavior

Companion Colab notebook for Kumaran et al. (2026), *Nature Machine Intelligence*.

This notebook reproduces the four-phase abstention paradigm reported in the paper, across four large language models. It is the experimental code release accompanying the publication — readers running it should be able to regenerate the data underlying the paper's main results.

---

## What the notebook does

The notebook implements:

- **Phase 0** (calibration): models answer 1000 multiple-choice questions; temperature-scaling parameter τ is fit on these to calibrate log-probabilities to empirical accuracy.
- **Phase 1** (chosen-confidence): models answer a separate 1000 questions with no abstention option. Confidence is extracted from logprobs and (separately) collected verbally.
- **Phase 2** (free abstention): same 1000 questions, but the model is told that some questions may have no correct answer and may abstain by outputting "5". This is the main behavioral measure of abstention.
- **Phase 3** (activation steering, Gemma only): high- and low-confidence steering vectors are constructed from residual-stream activations on a held-out question set, then injected during Phase 2 to causally manipulate confidence and observe the effect on abstention.
- **Phase 4** (instructed threshold): the model is given an explicit confidence threshold T and instructed to abstain when its confidence falls below it. Run across thresholds 0%–100% in steps of 10.

A separate **verbal confidence** pass is collected for each model after Phase 1, asking the model to classify its confidence in its prior answer into one of 10 ordered classes ("No chance" through "Almost certain").

### Provider notes

- **DeepSeek endpoint**: The published paper methods section references Together.ai for DeepSeek, but data was actually collected via DeepSeek's own beta endpoint (`api.deepseek.com/beta`). This will be corrected in the next revision of the paper. The model family and parameter count are identical.
- **Qwen provider split**: Main experimental phases (0, 1, 2, 4) were run via Together.ai. After Together.ai discontinued serving Qwen3-Next-80B-A3B-Instruct, the verbal confidence pass was collected via OpenRouter. Readers wishing to fully reproduce Qwen results today can use OpenRouter for all phases; minor numerical differences from inference backend variation are expected.

## Datasets

The notebook uses two non-overlapping question sets derived from the SimpleQA 4-way multiple choice dataset (Kumaran et al., 2025, built on Wei et al., 2024). Both are pre-prepared as CSVs and loaded directly.

### `phase0_questions.csv` — Calibration set (1000 questions)

Used in **Phase 0** to fit the temperature-scaling parameter τ (Guo et al., 2017) that calibrates each model's log-probabilities to its empirical accuracy.

- **Source**: rows 1000–2000 of `simpleQA_4MCQ_dataset_medium_cleaned.csv`
- **Size**: 1000 questions

### `phase1_questions.csv` — Main experiment set (1000 questions)

Used in **Phases 1, 2, 3, and 4** — the same 1000 questions across all four phases, enabling cross-phase per-question prediction.

- **Source**: `simpleQA_4MCQ_dataset.csv`, filtered to `gt_answer == 1`, first 1000 rows
- **Size**: 1000 questions
- All questions are answerable. Phase 2's "some questions may have no correct answer" framing is used to elicit abstention; there are no genuinely unanswerable items.

### Column schema (identical across both files)

| Column | Description |
|---|---|
| `question` | The factual question |
| `choice_1` | The ground-truth answer (before randomized shuffling at runtime) |
| `choice_2` | A similar foil |
| `choice_3` | A dissimilar foil |
| `choice_4` | An unrelated foil |

`choice_1` is the ground truth by convention. At runtime, the experiment code shuffles options into a fixed random order (seed `1042`) and tracks where the ground truth landed (`gt_position`). The same shuffle is applied to each question across all phases.

Phase 0 and Phase 1 question sets are disjoint by construction; this is verified at load time.

### Foil generation

Foils were generated by prompting Gemma 3 12B with each original SimpleQA question and ground-truth answer, asking it to produce a similar foil, a dissimilar foil, and an unrelated foil. Full details in the paper's Methods.

## Pre-computed covariates

The notebook uses three pre-computed input files alongside `phase1_questions.csv` to support the abstention regressions reported in the paper. These are loaded as-is — the notebook does not regenerate them.

All three are aligned row-by-row to `phase1_questions.csv` (same 1000 questions, in the same order, indexed by `question_index` 0–999).

### `phase1_difficulty.csv` — Question difficulty score

Per-question difficulty score = proportion correct across 20 independent runs of GPT-4o (Phase 1 prompt, `temperature=0.8`, fresh random choice arrangement per run).

| Column | Description |
|---|---|
| `question_index` | 0–999 |
| `question` | Question text |
| `n_correct` | Number correct across 20 runs |
| `n_runs` | 20 |
| `difficulty_score` | `n_correct / n_runs` (range [0, 1]; higher = easier) |

### `phase1_embeddings.csv` — Question sentence embeddings

First 10 principal components of sentence embeddings produced by `sentence-transformers/all-MiniLM-L6-v2`. Used as control for surface semantic features in the abstention regressions.

| Column | Description |
|---|---|
| `question_index` | 0–999 |
| `question` | Question text |
| `embed_pc1` … `embed_pc10` | First 10 PCs of MiniLM embedding |
| `choice_1_original` … `choice_4_original` | Pre-shuffle choice text (for reference) |

### `phase1_rag_scores.csv` — Wikipedia retrieval scores

Proxy for knowledge accessibility. For each question, the top 3 Wikipedia articles were retrieved via the `wikipedia` Python package, summaries truncated to 500 characters, embedded with MiniLM, and compared to the question embedding via cosine similarity. `rag_score` is the maximum similarity across the 3 retrieved documents.

| Column | Description |
|---|---|
| `question_index` | 0–999 |
| `question` | Question text |
| `rag_score` | Max cosine similarity between question and top-3 retrieved Wikipedia summaries |
| `rag_mean_similarity` | Mean cosine similarity across top-3 |
| `retrieval_success` | 1 if ≥1 article retrieved, else 0 |
| `retrieval_count` | Number of summaries successfully retrieved (0–3) |
| `retrieved_titles` | Pipe-separated titles of retrieved Wikipedia pages |

Retrieval was performed via the live Wikipedia API at the time of paper preparation. Wikipedia content changes over time, so the shipped CSV is the canonical source.

## Running the notebook

### Requirements

- **Colab runtime**: A100 80GB GPU for Gemma 3 27B (Phases 0, 1, 2, 4 and Phase 3 steering). Standard CPU runtime is sufficient for the API-based models (GPT-4o, DeepSeek, Qwen).
- **Google Drive mount**: the notebook reads and writes from `/content/drive/MyDrive/`. Adjust `the_dir` if your data lives elsewhere.
- **API keys**: OpenAI, DeepSeek, Together.ai, OpenRouter. All cells use `"XXX"` placeholders — replace with your own keys.

### Order of cells

1. Imports + Drive mount
2. Dataset preparation (creates `phase0_questions.csv` and `phase1_questions.csv` from source CSVs)
3. Verification + rename of pre-computed covariates (`phase1_difficulty.csv`, `phase1_embeddings.csv`, `phase1_rag_scores.csv`)
4. Per-model API client setup cells (OpenAI, DeepSeek, Together.ai, OpenRouter)
5. Gemma model load cell (skip if not running Gemma)
6. **GPT-4o**: Phases 0, 1, 2, 4 — then verbal confidence
7. **Gemma 3 27B**: Phases 0, 1, 2, 4 — then verbal confidence
8. **Gemma Phase 3 Cell A**: vector construction activation collection
9. **Gemma Phase 3 Cell B**: steering vector construction + injected Phase 2 evaluation
10. **DeepSeek**: Phases 0, 1, 2, 4 — then verbal confidence
11. **Qwen 80B**: Phases 0, 1, 2, 4 (Together.ai) — then verbal confidence (OpenRouter)

Each experimental cell has a `TEST_MODE` flag for a 10-question sanity check before scaling up.

### Test runs

Every experimental cell can be run with `TEST_MODE = True` for a 10-question sanity check (a few minutes per model). Sanity-check snippets in the notebook verify row counts, accuracy ranges, NOTA rates, and the absence of empty generations or extraction failures.

## Known limitations and behaviors

### Transformers attribute path (Gemma)

The Phase 3 cells use the attribute path `model.language_model.model.layers` to access decoder layers. This path is correct for current `transformers` versions but may differ on older releases. If readers hit `AttributeError` on Gemma cells, a diagnostic snippet in the notebook prints the correct path for their installed version.

### DeepSeek API behavior

DeepSeek requires `temperature=0.7` because logprobs are not available at `temperature=0` on the beta endpoint. At this sampling temperature, the model occasionally produces effectively empty completions — sampling a single whitespace token then halting (`finish_reason=stop`, completion is `' '` or `' \n'`). After `.strip()` parsing, these are recorded as empty `generated_text`.

In the published data, empty completions occurred in approximately 10% of trials overall, distributed unevenly across phases:

| Phase | Empty rate (published) |
|---|---|
| Phase 0 | 0.0% |
| Phase 1 | 0.4% |
| Phase 2 | 0.4% |
| Phase 4 | 6–25% depending on threshold |

Empty completions are coded as `final_answer='1'`, `is_nota=0` via the highest-logprob fallback (which tie-breaks to choice 1 when all logprob slots return the -50 placeholder). This is intrinsic DeepSeek sampling behavior at the required temperature, was present in the original runs, and is reflected in the published numbers.

The DeepSeek beta endpoint behavior appears to have shifted since original data collection; readers running the code today may observe higher empty-completion rates than those reported above, especially on the short-token phases. This affects reproducibility of exact numbers but does not affect the qualitative pattern of confidence-driven abstention reported in the paper.

### Qwen provider availability

Together.ai discontinued serving Qwen3-Next-80B-A3B-Instruct between the time of paper data collection and the notebook release. The notebook's main Qwen cells still point at Together.ai for documentation purposes (this is what produced the published numbers), but will fail at runtime. Readers wishing to reproduce Qwen results today should redirect those cells to OpenRouter (which still serves the model) by changing the client setup and model name string. Minor numerical differences from inference backend variation are expected.


### Gemma Phase 4 prompt

The GPT-4o Phase 4 prompt produced near-zero abstention rates on Gemma 3 27B (<5% below the 80% threshold). The paper used a paraphrased Gemma-specific Phase 4 prompt generated by Gemini 2.5 Pro, selected from 20 candidates as the variant that achieved highest abstention at T=100% (Extended Data Fig. 6). The notebook uses this paper-selected paraphrase for Gemma's Phase 4.


### Steering vector construction temperature

The Phase 3 steering vector construction uses a calibrated softmax temperature of 5.1 (derived from Gemma's Phase 0 calibration) for selecting top/bottom-margin trials. The output confidence values stored in the CSV files use `scaling_temperature=1` (raw softmax of logprobs); readers can apply their own calibration as needed for downstream analyses.
